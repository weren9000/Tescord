# Квачат: правила работы

## Структура и команды

- `frontend/`: Angular 21, TypeScript, SCSS. `backend/`: FastAPI, PostgreSQL, Redis, LiveKit.
- `desktop/` и `mobile/` упаковывают frontend для Windows и Android.
- Команды frontend выполняются в `frontend`: `npm ci`, `npm run lint`, `npm run format:check`, `npm run build`.
- UI: сначала `npx playwright install chromium`, затем `npm run test:ui`. Команда занимает порт 4217 и запускает только локальные сценарии с тестовыми данными. Подробности: `docs/frontend-tooling.md`.
- Интеграционные тесты backend запускать только на отдельной локальной тестовой БД. Не направлять тестовые фикстуры на рабочие данные.
- После проверки Android закрывать Android Emulator и проверять, что он завершил работу. Не оставлять эмулятор открытым.

## Интерфейс

- Третий переключаемый стиль — «Звёздный атлас»: `docs/design/star-atlas.md` и `docs/design/star-atlas/reference.png`. Бумажные поверхности, тёмные чернила и авторский атлас значков изолированы значением `data-ui-style='star-atlas'`.

- Второй переключаемый стиль — «Созвездие»: `docs/design/constellation.md` и `docs/design/constellation/reference.png`. Изменения этого стиля изолировать от «Эмали»; выбор сохраняется на устройстве в меню «Оформление».

- Базовый стиль приложения — эмаль: `docs/design/enamel.md`. Для стандартных панелей, кнопок, полей и диалогов этот документ приоритетнее прежних правил рисованных текстур. Иллюстрации, логотип и навигационные значки сохраняют утверждённые оригиналы.

- Эталон нового оформления — `docs/design/reference.png`, правила — `docs/design/cosmic-friends.md`. Для задач в этом стиле использовать навыки `kvachat-cosmic-ui` и `kvachat-cosmic-assets` (копии в `docs/design/skills/`). Стиль подключён к стартовой странице и общим элементам приложения; область перехода и проверки — `docs/design/painted-controls/application-rollout.md`.
- Иконки и кнопки рисованного набора: эталон `docs/design/painted-controls/reference.png`, подключение `docs/design/painted-controls/README.md`. Готовые компоненты — `frontend/src/app/shared/painted-controls/`. Этот набор не означает автоматическую замену всех иконок приложения.
- Использовать существующую палитру `frontend/src/_palette.scss`, CSS-переменные и общие компоненты. Сначала искать аналог в интерфейсе групп и звонков.
- Не добавлять Tailwind, Material или другую UI-библиотеку ради локального изменения.
- Сохранять единые размеры кнопок, отступы, типографику, скругления и набор иконок. Панель звонка должна оставаться на одном уровне.
- Согласованная шкала скруглений: 8 px для полей и компактных элементов, 12 px для обычных кнопок и карточек, 16 px для крупных панелей и диалогов. Использовать общие `--ui-radius-*`. Круглые аватары и круглые кнопки сохраняют 50%; полноэкранные мобильные окна — 0. Рисованные края текстур подгонять под эту шкалу, а не обрезать CSS-радиусом.
- Кнопкам с иконками нужны доступные названия и понятные состояния. Диалоги должны закрываться клавишей Escape и сохранять доступность с клавиатуры.
- Проверять длинные имена, загрузку, ошибки, пустые списки, темы, мобильную ширину 320–393 px и настольные экраны. Не допускать случайного горизонтального скролла.
- В комнате без демонстрации показывать плитки всех участников с именами, аватарами или видео. Во время демонстрации показывать рядом только включённые камеры; полосу камер можно свернуть. Полный список и индивидуальная громкость доступны через панель участников; общую громкость не возвращать без запроса.
- После изменений звонков проверять вход, повторный вход, начало/остановку демонстрации и выход. Для изменения аудио проверять действительный аудиосигнал, а не только положение ползунка.
- Для визуальных изменений просматривать снимки затронутых экранов; не считать успешную сборку доказательством удобства интерфейса.

## Проверки и изменения

- Форматировать только затронутые файлы: `npm run format -- src/path/to/file.ts`. Не смешивать массовое форматирование с функциональными исправлениями.
- `eslint-suppressions.json` и `format-baseline.json` фиксируют старый долг. Не расширять их для обхода новых замечаний. Уменьшать долг отдельными понятными изменениями.
- `npm run lint:all` и `npm run format:check:all` показывают полный долг. Обычный lint учитывает старые подавления; это не свидетельство отсутствия всех проблем.
- Не записывать ключи, пароли, токены, локальные пути к подписи и рабочие runtime-конфигурации в Git, отчёты и снимки.
- Не менять версии приложений и не публиковать релиз ради настройки инструментов разработки. Деплой нужен, когда меняется выпускаемое приложение и входит в задачу.
- На сервере хранить текущий релиз и максимум две предыдущие сборки для отката. После успешного деплоя и проверки удалять более старые каталоги релизов и архивы сборок. Перед удалением проверить, что текущий релиз и выбранные резервные сборки сохраняются. Это ограничение относится к сборкам приложения; резервные копии БД, файлов пользователей и ключей имеют отдельную политику хранения.

## Локальные данные деплоя

- Для запрошенного деплоя читать SSH-адрес, порт, логин и пароль из `.local/deploy-credentials.ini`, секция `[ssh]`, поля `host`, `port`, `username`, `password`. Если файл заполнен, не запрашивать эти данные повторно.
- Читать файл программно, не выводя содержимое или значения секретов в терминал, чат и логи. Для Python использовать `configparser.ConfigParser(interpolation=None)` и кодировку `utf-8-sig`, чтобы символы `%` в пароле не интерпретировались. Значения указаны без кавычек.
- `.local/` исключена из Git. Не включать файл в коммиты и архивы релиза, не передавать пароль в аргументах командной строки. Отсутствующие или пустые обязательные поля попросить заполнить локально. Наличие учётных данных само по себе не является запросом на деплой.
