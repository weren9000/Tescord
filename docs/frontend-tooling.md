# Инструменты frontend

Открывайте корень этого репозитория в VS Code. В `.vscode` сохранены рекомендации расширений и настройки ESLint/Prettier. Angular Language Service уже работает со `strictTemplates`.

## Установка

Нужен Node.js 22.13+ (CI использует Node 22), npm и установленные зависимости:

```powershell
cd frontend
npm ci
npx playwright install chromium
```

Расширения редактора не заменяют npm-зависимости. Prettier берёт настройки проекта и форматирует файл при сохранении. Первое сохранение старого компактного файла может дать большой diff: такие изменения лучше выделять отдельно.

## Команды

| Команда в frontend | Назначение |
| --- | --- |
| `npm run lint` | TypeScript и Angular HTML, включая встроенные шаблоны и правила доступности |
| `npm run lint:all` | Все замечания, включая существующий долг |
| `npm run format:check` | Новые и изменённые файлы должны соответствовать Prettier |
| `npm run format:check:all` | Полная проверка форматирования |
| `npm run format -- src/path/file.ts` | Форматирование выбранного файла |
| `npm run test:ui` | Запуск Angular и двух существующих UI-сценариев |
| `npm run test:ui:report` | Открытие HTML-отчёта со снимками |
| `npm run build` | Production-сборка |

## Постепенное внедрение

`eslint-suppressions.json` хранит исходные замечания ESLint по файлу и правилу. Новые превышения счётчиков вызывают ошибку, но замена одного старого нарушения другим того же правила может не обнаруживаться. Поэтому редактор и `lint:all` остаются важны. При исправлении долга удаляйте лишние подавления командой `npx eslint src --prune-suppressions`; не создавайте новые автоматически в CI.

`format-baseline.json` хранит SHA-256 нормализованного LF-содержимого старых неформатированных файлов. Пока содержимое не меняется, файл допускается; любое изменение требует форматирования. Генерируемый `src/index.html`, зависимости, сборки и ресурсы исключены. Файл baseline не обновляется проверкой.

## UI-проверки

Playwright Test запускает существующие `meeting-layout-smoke.cjs` и `participant-audio-smoke.cjs`, сохраняя их проверки. Тесты проверяют разные размеры экрана, панели, индивидуальную громкость по PCM-сигналу, демонстрацию и диалоги. Они используют локальный dev server на порту 4217 и подменённые API-ответы; аккаунты и backend не нужны.

Порт должен быть свободен: чужой dev server не переиспользуется. Для своего Chromium можно задать `CHROME_BIN`; по умолчанию используется браузер, установленный Playwright. Windows, Android и настоящий WebRTC-сервер этими двумя сценариями полностью не проверяются.

Отчёт находится в `frontend/playwright-report`, снимки также в `.local/room-design` и `.local/participant-audio`. Это пока не автоматическое сравнение с визуальными эталонами. Эталоны и отдельная галерея общих компонентов — следующий этап.

Существующие серверные сценарии `meeting-room-smoke.cjs` и `room-account-smoke.cjs` остаются отдельными: им нужны изолированные API, БД и LiveKit. Не включать их в обычный `test:ui` без такого окружения.
