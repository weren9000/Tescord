# Главная KVA Chat

Локальная реализация, без деплоя. Публичный `/` показывает главную; `/login` — вход и регистрацию. Сохранённый вход, приглашения, ссылки каналов и нативные приложения обходят главную.

Контент и CSS находятся в `frontend/src/app/landing`. `frontend/scripts/prepare-landing.cjs` включён в `prebuild`: он переносит тот же контент в исходный HTML, поэтому описание и скачивания доступны без JavaScript. Angular загружает компонент отдельным чанком. Лимит initial bundle увеличен с 1.60 до 1.62 MB: измеренный размер после изменения — около 1.604 MB; предупреждение 1.55 MB сохранено.

Изображение `landing-chat.png` снято с текущего интерфейса локального тестового аккаунта. Только для снимка подставлены демонстрационные имена и текст; реальные пользовательские переписки не использованы. Превью ссылки — `og-kvachat-landing.png`.

## Локальная подготовка

1. `python scripts/prepare-downloads.py` — проверяет SHA-256 существующих EXE/APK и копирует их в игнорируемый `frontend/public/downloads`.
2. `npm run build --prefix frontend`.
3. `python scripts/preview-frontend.py` — `http://localhost:4200`. Для входа нужен локальный API на 8000.
4. `node scripts/landing-smoke.cjs` — размеры 320/393/768/1024/1440, порядок Android, вход/назад, обход для native, приглашения, HTML без JS, полная загрузка обоих файлов и SHA-256. При `KVA_TEST_FIXTURE` дополнительно проверяет вход локальным тестовым аккаунтом и повторное открытие главной с сессией. Требуется Playwright из desktop и Chromium (`KVA_CHROME` задаёт путь).

Установщики не входят в Git и не пересобирались. При следующей сборке нативных приложений каталог downloads исключается из их web-ресурсов.

## При последующем разрешении на деплой

Обновить nginx-конфигурацию из `scripts/nginx-kvachat.conf`: новый маршрут `/login` и типы файлов `/downloads/`. `deploy-release.sh` вызывает `persist-downloads.py`, который проверяет контрольные суммы, переносит файлы в `/srv/tescord/downloads` и связывает с ним каталог релиза. Имена версионные: файл с тем же именем и другим содержимым заменить нельзя. При следующих релизах старые скачивания сохраняются. `package-release.py` не позволит упаковать страницу с отсутствующими файлами скачивания.

Linux-операции с symlink и nginx следует проверить при подготовке деплоя: на текущей Windows создание symlink запрещено правами. Серверные файлы и настройки в рамках этой задачи не изменялись.
