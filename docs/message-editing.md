# Редактирование сообщений

Автор может исправить текст сообщения или подпись к существующим вложениям без ограничения по времени. В меню сообщения — карандаш; в нижнем поле — галочка сохранения и крестик отмены. Отметка «изменено» содержит подсказку с временем изменения. Удалённые и системные сообщения не редактируются.

Исходный черновик, выбранный ответ и подготовленные файлы восстанавливаются после сохранения/отмены. Незавершённые правки основной переписки сохраняются в памяти при переходе между чатами до выхода из аккаунта или перезагрузки страницы. Escape сначала закрывает панель эмодзи/упоминаний, затем отменяет правку. На ПК Enter сохраняет, Shift+Enter переносит строку; Ctrl/Cmd+Enter также сохраняет. На сенсорном устройстве Enter переносит строку.

`PATCH /api/messages/{id}` принимает `content` и обязательное nullable-поле `expected_edited_at`. Блокировка строки и проверка версии предотвращают молчаливую перезапись с другого устройства. При конфликте возвращается 409 с актуальным сообщением: пользователь видит его рядом со своей правкой и может явно применить свою версию. Повтор запроса с уже сохранённым текстом не меняет время редактирования.

Событие `message_updated` содержит только текст, идентификаторы, отметки изменения/удаления и упоминания. Клиент сохраняет собственные реакции и прочтения, обновляет цитаты и открытые результаты поиска. Список бесед обновляется обычным событием без уведомления о новом сообщении. Отправка push для редактирования не вызывается. После переподключения используется существующая повторная загрузка истории.

Миграция `20261030_0055` добавляет `messages.deleted_at` и отделяет старые заглушки удаления от редактирования. Выпуск требует миграции БД вместе с backend/frontend. Вложения при правке не заменяются; пустой текст разрешён только при наличии неудалённого вложения. Лимит основной переписки — 20 000 символов, комнат встреч — существующие 10 000.

В комнатах встреч сохранён существующий механизм обновления через `chat_revision`; добавлены проверка версии, сохранение черновика и кнопки с иконками. При конфликте там остаётся введённый текст и сообщение об ошибке; для повторного редактирования актуального сообщения нужно сохранить свою правку и открыть сообщение заново.

## Проверки

- Backend: `pytest tests/test_message_editing.py tests/test_meeting_rooms.py tests/test_conversations.py tests/test_app_event_json.py` только с отдельной локальной тестовой PostgreSQL.
- UI: `npx playwright test --config playwright.message-edit.config.ts` запускает отдельный сервер на 4229. Сценарии используют подменённые API; реальное событие второму клиенту проверяется backend-тестом с WebSocket.
- UI-снимки сохраняются в `frontend/test-results`: меню, правка на ПК и 320–393 px, светлая/тёмная палитры, конфликт и чат встречи.
