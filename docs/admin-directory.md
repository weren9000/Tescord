# Административный каталог

## Пользователи и валюты — 20 октября 2026

В таблице пользователей видны монеты, кристаллы и количество активных экземпляров предметов. Балансы и количество предметов можно сортировать. Фильтр «У кого есть предмет» ищет владельцев по названию или ID предмета, исключая отозванные экземпляры. В карточке пользователя доступны профиль, кошелёк с историей и инвентарь с группировкой копий, категориями, редкостью и статусом использования.

Выбор пользователей сохраняется между страницами. «Выбрать всех по фильтру» получает фиксированный список ID с сервера; одна операция ограничена 1000 получателями. Массовая операция задаёт одну валюту, начисление/списание, сумму каждому и обязательную причину. Перед подтверждением показываются получатели, балансы до/после, сумма и причины пропусков.

`POST /api/admin/wallet-batches/preview` сохраняет параметры и предпросмотр, не меняя деньги. `POST /api/admin/wallet-batches/{id}/confirm` блокирует пакет и кошельки в стабильном порядке, выполняет допустимые изменения и сохраняет результат в той же транзакции. Повторное подтверждение возвращает прежний результат. Недостаток средств, удалённые пользователи и изменившийся после просмотра баланс приводят к пропуску соответствующего получателя. Автоматического повторного списания с новым балансом нет. Успешные изменения связаны с пакетом через `wallet_operations.batch_id`; сохраняются автор, причина, сумма и итоговый баланс. Доступ имеет только системный администратор, в том числе к результату своего пакета.

Незавершённая операция восстанавливается из локального хранилища через кнопку «Продолжить операцию», включая перезагрузку после потери ответа сервера. Одиночные операции используют существующий API кошелька, защиту от повторов и проверку ожидаемого баланса.

Миграция `20261020_0048` добавляет таблицу пакетов и необязательную ссылку на пакет в истории кошелька. Она совместима с предыдущим серверным кодом. Клиенты: Windows 0.5.6, Android 0.3.9 (`versionCode 13`), прежний ключ подписи APK.

Проверки: 154 backend-теста полного прогона, 6 пропущенных тестов Redis; дополнительно целевой набор из 5 тестов массовых операций. 57 frontend-тестов, production build, Playwright `scripts/admin-users-smoke.cjs` с реальным API и отдельной БД (потеря ответа после фиксации, перезагрузка, отсутствие двойного начисления, одиночное списание, инвентарь и мобильный экран). Windows: запуск собранного приложения и проверка нативного моста; Android: assembleRelease, lintDebug, подпись и браузерная проверка моста. Проверка на физическом Android-устройстве остаётся отдельной.

## Первый выпуск

Кнопка «Админка» доступна системным администраторам и администраторам предметов в левой панели и меню приложения. Администратор предметов видит только вкладку «Предметы». Системному администратору также доступны пользователи, группы и площадки, серверный поиск и сортировка, фильтры ролей/владельца, страницы по 24 или 48 записей. Фильтры и положение списка сохраняются при смене вкладок. Подробности открываются справа, на телефоне — на весь экран.

API `/api/admin/directory` проверяет `User.is_admin` на каждом запросе, выдаёт `Cache-Control: no-store`, выбирает только необходимые поля. Email доступен в подробностях пользователя. Пароли, сессии, токены, переписка и прямые диалоги не выдаются. Связанные списки участников, каналов и пространств пользователя имеют собственную пагинацию. Поля поиска экранируют SQL wildcard-символы; порядок выдачи стабилизирован ID.

Пользовательские аватары и загруженные иконки поддерживают `preview=true`: статический WebP до 96×96, кеш по хешу исходника, атомарная запись. Эти миниатюры показывают аватар без декоративной рамки. Оригиналы и обычные URL не изменены. При ошибке картинки карточка показывает инициалы.

В этой версии нет изменения ролей, блокировки и удаления. В текущей модели нет глобального состояния блокировки аккаунта, поэтому соответствующий статус и фильтр не имитируются. Списки каналов показывают название и тип; управление доступом и приглашениями остаётся отдельной задачей. Новых миграций БД нет.

Проверено: 32 frontend-теста; 5 backend-тестов каталога и превью; production build. Браузер на 1440×1000, 1280×720, 390×844 и 320×740: вкладки, подробности, поиск, пустой результат, сохранение фильтра, ошибка/повтор, закрытие при 403, вход из мобильного меню и отсутствие горизонтальной прокрутки. Материалы: `D:/Code/Kva/admin-directory-review/`. Сохраняется прежнее предупреждение о размере основного SCSS.
