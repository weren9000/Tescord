# Исправления безопасности, ноябрь 2026

Формы `multipart/form-data` и `application/x-www-form-urlencoded` теперь проходят проверку сессии до чтения тела. URL-encoded тела ограничены 64 КиБ; загрузки иконок и профиля имеют отдельные пределы. Иконки и аватары проверяются по фактическому формату и числу пикселей, уменьшаются до 512 px и сохраняются без исходных метаданных. Предпросмотр старых файлов также ограничивает память и число одновременных декодирований.

Публичные DTO сохраняют строковое поле `login` для совместимости старых клиентов, но содержат в нём публичный ID. Почта доступна своему владельцу и в предусмотренных административных API. Создание групп и адресное добавление участников проверяют личные блокировки в обе стороны; проверка сериализована с изменением блокировок.

Обновлены Pillow, Starlette, python-multipart, pydantic-settings и certifi. Минимальные безопасные версии закреплены в pyproject и lockfile; плагин календаря также переведён на исправленные Pillow/Starlette/certifi.

## Переход существующего сервера на временные TURN credentials

Этот переход требует публикации backend, веб-клиента и новых сборок Windows/Android. `deploy-release.sh` отклоняет старый runtime-config с TURN-полями до миграций; для первого переключения передайте путь к подготовленному публичному файлу через `TESCORD_RUNTIME_CONFIG_PATH`. Изменение файлов репозитория само по себе не удаляет старый пароль из рабочего runtime-config или ранее скачанных приложений.

1. Сгенерировать **новый** случайный общий секрет не короче 32 символов на сервере. Не использовать опубликованный старый TURN-пароль. Сохранить секрет только в защищённом окружении backend (`TESCORD_TURN_SHARED_SECRET`) и конфигурации coturn (`static-auth-secret`). Настроить `TESCORD_TURN_URLS` и `use-auth-secret`. Пример: `infra/coturn/turnserver.conf.example`.
2. Проверить адрес LiveKit, доступный TURN-серверу. Пример запрещает приватные и локальные адреса назначения; если SFU использует приватный адрес, разрешить **один его адрес** через `allowed-peer-ip`. Проверить IPv4/IPv6 и квоты под ожидаемую нагрузку. Не разрешать весь приватный диапазон.
3. Выполнить переход в окно обслуживания либо использовать отдельный временный TURN-listener для проверки. Подготовить согласованные backend/frontend/native-сборки и удалить постоянного пользователя coturn при переключении. Не считать удаление пароля из JS отзывом уже выданного пароля.
4. Опубликовать runtime-config только с публичными адресами API/WebSocket/SFU. Новый `scripts/native-runtime.cjs` включает только эти адреса и не читает старые TURN credentials из локального JSON. Перевыпустить клиенты: старые установленные версии продолжают содержать прежние данные и не используют новый ответ API.
5. Проверить звонок через relay из двух сетей: вход, повторный вход, камеру, начало/остановку демонстрации и выход. Проверить обычный канал, личный звонок и гостя комнаты. Старый пароль должен перестать создавать allocations, а анонимный запрос к media API — не получать новые credentials. Не печатать пароли, токены или полный ответ media API в журнал.

API возвращает `ice_servers` только после обычных проверок допуска к медиа. Ответы не кешируются, браузер хранит credentials только в памяти. Срок по умолчанию — 24 часа, настраивается от 10 минут до 24 часов. Это ограничивает время повторного использования полученных credentials, но не является немедленным отзывом отдельной TURN allocation при выходе. Слишком короткий срок может мешать длительным звонкам и переподключениям; регулярное обновление credentials в уже открытом соединении в этот патч не входит.

Если внешний TURN не настроен, API возвращает пустой список, а клиент использует конфигурацию ICE, предоставленную LiveKit. Публичный статический пароль больше не применяется как запасной вариант.

Алгоритм генерации соответствует [TURN REST API coturn](https://github.com/coturn/coturn/blob/master/README.turnserver): username содержит время истечения и непрозрачный идентификатор, пароль — HMAC-SHA1, закодированный в Base64. Серверный общий секрет клиенту не передаётся.

## Проверки от 2 ноября 2026

- Backend: 212 тестов прошли на отдельной локальной PostgreSQL; 6 проверок кластерного состояния пропущены, поскольку тестовый Redis не настроен. Календарь: 18 тестов прошли.
- Все 57 зафиксированных Python-зависимостей повторно проверены через OSV: известных уязвимостей для установленных версий не найдено. `pip check` прошёл. Это результат проверки зависимостей на указанную дату, а не гарантия отсутствия всех уязвимостей приложения.
- Frontend: сборка, lint и проверка форматирования прошли; 125 unit-тестов прошли. Lint сохраняет два прежних предупреждения; 137 неизменённых файлов остаются в старом списке долга форматирования, список не расширялся.
- Локальный LiveKit и два браузерных клиента: личный звонок с передачей RTP в обе стороны, отложенным доступом к микрофону, камерой, включением/выключением демонстрации, восстановлением управляющего соединения и завершением прошёл.
- Гостевая комната: камера, звук, чат, файлы, ответы, выход и возвращение владельца, завершение для всех и мобильная ширина прошли. Громкость дополнительно проверена по реальному PCM-сигналу: коэффициенты для 100/50/10/0/75% соответствуют заданным значениям.
- Браузерные проверки выполнены в Chromium Headless Shell с искусственными камерой и микрофоном. В полном Chromium этой среды публикация камеры зависала; результат из Headless Shell не заменяет проверку физических устройств и Android/WebView.
- Синтаксис Bash/PowerShell/Node-скриптов публикации проверен. На этапе первичной проверки сборки Windows/Android и обновление сервера ещё не выполнялись.

Локальные медиапроверки использовали ICE от LiveKit. Выдача и подпись временных TURN credentials, срок действия и проверки допуска покрыты backend-тестами. Перед публикацией всё ещё нужна проверка внешнего coturn через relay из разных сетей, включая обычный голосовой канал, отзыв старого пароля и обновлённые нативные клиенты. До настройки и публикации на сервере эти исправления защищают только подготовленную версию кода.

## Подготовка публикации

Windows: установщик 0.5.31 с новым клиентом. Android 0.3.34 по решению владельца получает новый ключ подписи; ключ и пароль сохранены в защищённом локальном хранилище резервных копий, вне Git. Эта подпись отличается от опубликованной 0.3.33: обновление поверх старого APK невозможно, требуется удаление старого приложения и установка нового. Локальную сессию понадобится создать заново; серверные данные не удаляются при переустановке приложения. Сохранить новый ключ для всех следующих Android-релизов.
