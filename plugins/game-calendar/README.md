# Календарь игр — первый независимый плагин Квачата

Самостоятельное приложение: FastAPI, SQLite и браузерный интерфейс без сборщика. Не импортирует backend Квачата, не использует его базу, пользовательские токены и события. Работает без регистрации. Манифест доступен по `/plugins/game-calendar/manifest.json`; разрешения на данные чата не нужны.

Это первый доверенный плагин, а не загрузчик произвольных сторонних расширений. В Квачате добавлены только пункты открытия в навигации и меню. Полноценный каталог установок, права сторонних плагинов и iframe-мост не входят в эту версию.

## Возможности

- Ближайшие игры, все события и избранное; поиск по названию, региону, полигону, организаторам.
- Фильтры региона, типа и месяца; карточка события, ссылка организаторов и первоисточник.
- Избранное в localStorage текущего браузера. Синхронизации между устройствами пока нет.
- Ссылка на конкретную игру и экспорт `.ics` с правильной исключающей датой окончания.
- Мобильный интерфейс от 320 px, клавиатура и закрытие диалога Escape.
- Показ даты синхронизации, предупреждение об устаревшей копии, загрузка, пустой список и повтор после ошибки.

## Данные

Источник: https://kogda-igra.ru/ ; документация: https://kogda-igra.ru/api/ . API открыт для автоматизированного чтения. Ссылка и название источника видны в интерфейсе.

При первом запуске и смене года читаются индексы текущего и следующего года. HTML используется только для обнаружения ID: API не документирует выборку по году. Поля событий получаются через `/api/game/{id}`. Ежедневно читается `/api/changed/{timestamp}` с перекрытием 5 минут; раз в 7 дней дополнительно проверяются все сохранённые ID. `--full` заново обнаруживает события по годам. События вне текущего/следующего года удаляются при их проверке; неизвестные даты сохраняются без выдуманной даты.

Удаления, недоступные записи и перенаправления обрабатываются отдельно. Контактные email не сохраняются. Описания выводятся только как текст, внешние ссылки допускают HTTP(S). Ответы ограничены 5 MB, есть таймауты, 3 попытки и интервал не менее 0.2 секунды между запросами. Статусы и сроки не заменяются предположениями приложения.

Обновление одной транзакцией: при ошибке остаются прежние записи и курсор. Читатели видят целую предыдущую версию во время синхронизации. SQLite WAL и блокировка писателя защищают от параллельных запусков. Источник не вызывается при открытии страницы пользователем.

## Обложки из VK

Поле `vk_club` из источника (или ссылка VK в поле сайта) связывает игру с сообществом.
После обновления событий тот же ежедневный запуск запрашивает `groups.getById` пакетами по 50
сообществ: обложка, затем аватар. Закрытые и отключённые сообщества не показывают картинки.
При ошибках API или скачивания остаётся прежняя картинка. Если картинки ещё нет, показывается заглушка.
При первом обновлении старой базы события перечитываются один раз для заполнения связей VK.

Задайте `KVA_CALENDAR_VK_TOKEN_FILE` — путь к текстовому файлу с сервисным ключом вне репозитория.
Либо используйте серверную переменную `KVA_CALENDAR_VK_TOKEN`. Без ключа календарь работает без загрузки новых картинок.
Не храните ключ в Git, frontend или снимках экрана.

Для systemd создайте `/etc/kvachat/game-calendar.env` с `KVA_CALENDAR_VK_TOKEN_FILE=/etc/kvachat/game-calendar-vk.token`.
Файл токена должен быть доступен для чтения только владельцу и группе сервиса (например, `root:tescord`, режим `0640`).
Изолированный сервис обновления читает этот env-файл; публичному веб-сервису токен не нужен.
Для отдельного обновления картинок: `python -m game_calendar.sync --images-only`.

Картинки скачиваются только с HTTPS-поддоменов `userapi.com`, без перенаправлений, до 8 MB / 20 MP.
Они преобразуются в WebP до 1600×900, сохраняются рядом с базой в `images/` и раздаются с собственного домена.
Имена — хеш содержимого, HTTP-кеш — immutable; неизменившиеся файлы повторно не скачиваются.
В диалоге есть ссылка на сообщество-источник. Архивные файлы пока автоматически не удаляются;
при резервном копировании сохраняйте базу вместе с каталогом `images/`.

## Локальный запуск

Из этой папки, Python 3.12+:

```sh
python -m venv .venv
# Активировать .venv и затем:
pip install -e .
python -m game_calendar.sync
uvicorn game_calendar.app:app --host 127.0.0.1 --port 8012
```

Открыть http://127.0.0.1:8012/plugins/game-calendar/ . По умолчанию данные в `data/calendar.sqlite3`; путь можно задать через `KVA_CALENDAR_DB`. Первое заполнение занимает несколько минут. API до заполнения возвращает честное пустое состояние.

Для открытия из локального Квачата запустить frontend:

```sh
npm start -- --proxy-config proxy.game-calendar.json
```

## Развёртывание отдельно от Квачата

Рекомендуемая структура:

```text
/srv/tescord/plugins/game-calendar/
  current/      # содержимое plugins/game-calendar
  venv/         # отдельное окружение Python
  data/         # постоянная база, не внутри current
```

1. Подготовить каталоги, отдельное окружение, установить пакет и дать `tescord` права на `data`.
2. Установить файлы `deploy/*.service` и `deploy/*.timer` в `/etc/systemd/system/`.
3. Подключить `deploy/nginx.conf` внутри HTTPS server-блока Квачата до SPA fallback. Проверить `nginx -t`.
4. `systemctl daemon-reload`, запустить `kva-game-calendar-sync.service` для первой загрузки.
5. Включить `kva-game-calendar.service` и `kva-game-calendar-sync.timer`; перезагрузить nginx.
6. Проверить `/plugins/game-calendar/health`, `/plugins/game-calendar/api/events`, страницу и время обновления.

Таймер запускает обновление ежедневно около 03:00 UTC, пропущенный запуск выполняется после включения сервера. Это надёжнее cron на выключавшемся сервере. Если нужен именно cron, запускать **вместо** таймера под пользователем сервиса, с абсолютными путями к рабочей папке, Python и `KVA_CALENDAR_DB`.

Кнопку в основном приложении публиковать после запуска сервиса и маршрута nginx, чтобы не получить неработающую ссылку. При обновлении плагина сохранять `data` и перезапускать только его сервис. Для отката вернуть предыдущую папку `current`. Выпуск установщиков и перезапуск чата не требуются.

## Проверки

```sh
python -m unittest discover -s tests -v
```

Тесты требуют `httpx` (dev-зависимость), работают на временных базах и не обращаются к источнику. Из корня репозитория с установленным frontend Playwright и запущенным плагином:

```sh
node plugins/game-calendar/tests/browser.cjs
node plugins/game-calendar/tests/images-browser.cjs
```

Сценарии интерфейса используют локальные фикстуры, затем сохраняют снимки живой локальной копии в `artifacts/game-calendar/`.
