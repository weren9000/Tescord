# Острова · Квачат

Самостоятельная сетевая настольная игра на 3–4 человек, встроенная в «Приложения» Квачата. Рабочее название — «Острова». Реализованы комнаты по коду приглашения, готовность и выбор цвета, остров из 19 тайлов, начальная расстановка, кубики, пять ресурсов, дороги, поселения, города, разбойник, торговля с банком/портами/игроками, карты развития, награды и победа при 10 очках в свой ход.

Правила `classic-2020-v1` зафиксированы по базовой редакции 2020 года: https://www.catan.com/sites/default/files/2021-06/catan_base_rules_2020_200707.pdf. Это собственные название, интерфейс и сгенерированные иллюстрации. Рейтинг, боты, магазин и дополнения в эту версию не входят.

## Локально попробовать игру

Из корня репозитория, с установленными Python-зависимостями backend:

```powershell
$env:PYTHONPATH = (Resolve-Path plugins/islands).Path
backend/.venv/Scripts/python.exe plugins/islands/tests/serve_fixture.py --port 4229
```

Открыть три вкладки: http://127.0.0.1:4229/_test/?player=0, http://127.0.0.1:4229/_test/?player=1 и http://127.0.0.1:4229/_test/?player=2. Для четвёртого игрока — `player=3`. Первый создаёт партию, остальные вводят её код; все нажимают «Я готов», создатель начинает. Вкладки представляют разных вымышленных пользователей. Сервер слушает только loopback, создаёт временную БД и ключ. Рабочие аккаунты и переписка не используются. Остановка — Ctrl+C; временные партии удаляются.

Это настоящий игровой сервис с отдельной тестовой оболочкой входа. `tests/serve_fixture.py` и его маршруты `/_test/` никогда не входят в production-пакет.

Первый художественный образец оставлен отдельно: `node plugins/islands/scripts/preview.cjs`, http://127.0.0.1:4228. В нём семь демонстрационных гексов и свободное размещение, без сетевой игры. Полная игра находится в `web/play.html` и требует API.

## Как устроено

- `islands/engine.py` — правила и проекция состояния конкретного участника. Сервер определяет кубики, колоду и случайную кражу; браузер отправляет только намерения.
- `islands/store.py` — собственная SQLite в WAL, версии комнат и атомарные команды. Состояние, квитанция повтора и запись журнала фиксируются одной транзакцией. Основная БД чата не используется.
- `islands/api.py` — HTTP-команды и WebSocket-обновления; проверка участия, размера запроса, частоты действий и разрешённого источника.
- `web/game*.mjs`, `web/connection.mjs`, `web/game.css` — игровой интерфейс, масштабирование, подтверждение размещения, приватная рука, торговля и восстановление соединения.
- Основной backend выдаёт одноразовое разрешение на 60 секунд, подписанное отдельным Ed25519-ключом. Сервис игры знает только открытый ключ и получает ID/имя игрока. Основной токен Квачата не передаётся в игру.
- Игровая сессия хранится только в памяти браузера; в БД — её хеш. Обновление разрешения каждые 40 секунд ограничивает задержку отзыва доступа 90 секундами от последней выдачи. Подробности — `DEPLOYMENT.md`.

После обрыва связи повторяется тот же ID команды. Запоздавшие действия с другой версией получают конфликт и обновлённое поле. Перезагрузка страницы требует нового разрешения и возвращения в «Мои партии». Перезапуск сервиса сохраняет партии. Пауза ручная; её снимает автор или создатель комнаты. Завершение начатой партии без победителя требует согласия всех участников. Автоматических ходов вместо отсутствующего игрока нет.

Игра открывается внутри Квачата; текущий звонок сворачивается в общую панель. Черновик чата и состояние звонка остаются в основном приложении. Запись каталога включается только при `ISLANDS_ENABLED=true` и настроенном ключе. По умолчанию функция выключена до отдельной публикации сервиса.

## Графика

45 рабочих WebP, около 4 МБ: 19 разных тайлов шести типов местности, пять ресурсов, пять карт развития и рубашка, 12 фишек четырёх цветов, разбойник, порт и море. Детали упрощены по пожеланию пользователя: крупные формы, спокойный центр под номер, выразительные силуэты. Подписи и числа рисуются интерфейсом, геометрия гексов задана кодом.

`art/source/` хранит исходные PNG, включая первую ревизию; `art/prompts*.json` — запросы и связи с образцами. Активные исходники определяются манифестами; восемь переработанных мастеров имеют суффикс `-v2`. Четырнадцать спрайтов имеют настоящий альфа-канал. `web/assets/manifest.json` фиксирует размеры, вес и SHA-256 исходников. В приложении генерации нет.

Повторная оптимизация, без изменения художественного содержания:

```powershell
node plugins/islands/scripts/prepare-assets.cjs
```

Нужны frontend-зависимости и Chromium Playwright. Палитра берётся из `frontend/src/_palette.scss`. Исходные PNG и запросы не раздаются пользователям и не включаются в серверный релиз.

## Проверки

Из корня репозитория:

```powershell
$env:PYTHONPATH = (Resolve-Path plugins/islands).Path
backend/.venv/Scripts/python.exe -m unittest discover -s plugins/islands/tests -p 'test_*.py' -v
node --test plugins/islands/tests/board.test.mjs plugins/islands/tests/connection.test.mjs
node plugins/islands/tests/browser.cjs
node plugins/islands/tests/multiplayer.cjs
```

В `frontend`:

```powershell
npm run lint
npm run format:check
npm run build
npm run test:ui -- e2e/islands.spec.ts e2e/applications.spec.ts e2e/call-chat.spec.ts
```

Python проверяет геометрию, правила, четыре полные партии на 3/4 игроков до победы с сохранностью ресурсов, подписи и повтор разрешений, изоляцию чужих карт, конкурентные команды, восстановление БД, ограничения и интеграцию выдачи разрешения. Все хранилища тестов временные; основной backend подключается с заменёнными зависимостями, без рабочей БД.

Браузерные сценарии проверяют три сетевых клиента, расстановку, ход, перезагрузку, паузу, диалоги, темы, графику и ширины 320/393/1024/1440 px. Angular-сценарии проверяют встраивание, отказ/повтор входа, фильтрацию сообщений iframe и сохранение состояния звонка на фикстурах. Это не проверка реального медиасигнала. Снимки находятся в игнорируемых `artifacts/islands*` и `frontend/test-results`.

### Полная партия через интерфейс — 2 ноября 2026

Пройдена партия за трёх тестовых игроков в отдельных контекстах Chromium: Аня (1440×1000), Борис (1024×900), Вера (393×851). Решения о размещении, обменах и картах принимал агент по игровому интерфейсу; Playwright выполнял нажатия и ввод. Игровые команды отправлял сам интерфейс. Прямые вызовы API, подмена кубиков, выдача ресурсов и изменение БД для ускорения партии не использовались. Локальный сервис работал с временной БД и случайными серверными кубиками/колодой.

На 59-м ходу Борис построил поселение и выиграл. Итог: **Борис 10, Аня 9, Вера 8**. У Бориса — три города, поселение, самая длинная дорога (9 участков) и скрытое победное очко; у Ани — два города, три поселения и крупнейшая армия (3 рыцаря). Результат и окончательные очки синхронизировались во всех трёх клиентах, игровые действия стали недоступны. Перезагрузка всех трёх страниц сохранила итог.

В этой партии выполнены 13 обменов между игроками, отказ и отмена предложения, 10 корректных обменов с банком, 16 перемещений разбойника с кражей, сброс 4 из 8 ресурсов, 8 улучшений до города и все виды карт развития. Проверены две бесплатные дороги до броска без списания ресурсов, «Изобилие», «Монополия», рыцари до броска, запрет немедленного розыгрыша купленной карты и скрытый счёт до завершения. При равенстве дорог награда осталась у Веры; маршрут Бориса из 7 участков затем забрал её. Две попытки обмена с неверным курсом были отклонены без списания карт. В частности, одно выбранное береговое место оказалось без порта: берег сам по себе не даёт скидку. Курсы приобретённых портов отобразились правильно; отдельные успешные обмены по 2:1 и 3:1 в этой партии не выполнялись (правила портов дополнительно покрыты тестами движка).

После прохождения исправлены оставшиеся кубики предыдущего хода, отсутствие сообщения об отказе автору обмена, доступные названия списков получателя/ресурса, курс банка внутри формы и русские подписи. В подтверждении поселения/города теперь явно указаны порт с курсом либо отсутствие порта. Повторная проверка: **34 Python-теста, 3 Node-теста и сценарий трёх браузерных клиентов прошли**, включая отказ без изменения рук, очистку кубиков на следующем ходу, диалог банка на 320 px и перезагрузку. Ошибок JavaScript в полной партии и повторном сценарии не зарегистрировано; снимки изменений просмотрены.

Локальные свидетельства: `artifacts/islands-playthrough/actions.jsonl` (действия UI и игровые команды без токенов), `action-summary.json`, `final-after-reload.json`, `19-winner-boris.png`, `21-game-ended-mobile.png`. Новые проверки интерфейса и снимки — `artifacts/islands-multiplayer/`. Эти артефакты исключены из Git. Одна партия не доказывает отсутствие всех редких ошибок; полный ручной прогон на четырёх клиентах, успешные портовые обмены через UI и физический Android в этот проход не входили. Публикация этим прохождением не выполнялась.

В Android 16 Emulator проверена настоящая WebView отдельной debug-оболочки: iframe с адресом `https://kvachat.ru/plugins/islands/`, вход с тестовым разрешением, партия с двумя браузерными клиентами, возврат после 95 секунд в фоне, синхронная пауза/продолжение, диалог и восстановление после перезагрузки iframe. HTTPS/WS-запросы в этом сценарии перехватываются и направляются в локальный сервис с временной БД; основной backend и рабочие аккаунты не используются. Исправлено узкое разрешение навигации iframe в `MainActivity.java`, помимо CSP оболочки. Эмулятор закрыт после проверки. Реальные звонки и физический Android этим сценарием не проверяются.

Повтор Android-сценария: подготовить свежие web-ресурсы (`node mobile/prepare-web.cjs`, затем `npm run sync` в `mobile`), собрать `:app:assembleDebug` из `mobile/android` с `--init-script ../../plugins/islands/tests/android.init.gradle`, установить debug APK в эмулятор и выполнить `node plugins/islands/tests/android.cjs` из корня. Init script задаёт отдельный ID `ru.kvachat.islandscheck` и не меняет release-настройки/подпись. Нужны Java 21, SDK из `.tools/sdk` и запущенный эмулятор; ID по умолчанию `emulator-5554`, другой задаётся `ISLANDS_TEST_EMULATOR`. Сценарий закрывает указанный эмулятор в `finally`, в том числе при ошибке. Для воспроизводимости запускайте эмулятор без загрузки старого snapshot (`-no-snapshot`) и устанавливайте актуальный тестовый APK. Этот APK не публиковать как Квачат.

Инструкции установки, включения, резервирования и отката — `DEPLOYMENT.md`. Git-публикация и деплой выполняются отдельной задачей; локальная реализация не включает игру на рабочем сервере автоматически.
